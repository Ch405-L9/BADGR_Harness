# Media Plan

No media is created by this branch. The following proposals are for real assets the owner may capture later from verified behavior.

| Proposed asset | What it proves | How to capture it later | Privacy checks before publishing | Destination |
|---|---|---|---|---|
| Architecture diagram | The confirmed core components and their boundaries | Draw only from the reviewed router, orchestrator, validator, schemas, optional boundaries, logging, and state code | Remove local paths, usernames, hostnames, credentials, private collection names, unrelated systems, and unverified claims | README or portfolio case study |
| Real sanitized routing-test output | The distinction between generic routing and domain-gated specialist routing | Run an owner-approved routing test and capture the actual output | Remove machine paths, environment details, private prompts, credentials, and unsupported totals; preserve the real command and result | README or case study |
| Failure/correction artifact | The documented routing risk and the correction that addresses it | Capture a real test or history excerpt after owner verification | Confirm the excerpt is accurate, contains no private content, and does not imply unverified production or security claims | Case study |
| Optional short walkthrough | A reviewer’s route through the verified core behavior | Record a real local mock or approved local run | Inspect video and audio for private data, local configuration, credentials, unrelated projects, and hidden metadata | Portfolio location chosen by owner |

Each asset should be based on actual repository behavior or history. Do not fabricate screenshots, terminal output, diagrams, metrics, or before/after results.
